### 参考: 感度分析「家を出る時刻を 6:30 からにした場合」(2026-10-08。確定数値は変えない)

確定版は家を出る時刻を **7:00〜10:30 の30分おき**で試している。通院に使える朝のバスが7時すぎの1本しかない
地区では「7:00ちょうどに家を出てその便に間に合うか」で判定が分かれるため、いちばん早い出発を 6:30 にして
計算し直した(`python3 gap_map/sensitivity_depart.py`。分析日のネットワークをそのまま使い、確定版と同じ
条件で計算し直すと通院可能性・空白判定・地図①の色分けが全817メッシュで一致することを確かめてから比べる)。

| 指標 | 確定版(7:00〜) | 6:30〜 |
|---|---|---|
| 空白メッシュ人口 | 15,418人(5.6%) | 14,850人(5.4%) |
| 隠れ空白 | 9メッシュ・571人 | **1メッシュ・3人** |
| 通院できる(Yes)メッシュ | 585 | 597 |

- **判定が変わったのは山寺地区の12メッシュ・667人だけ**。山形市内行きの朝の便が 7:01(山寺駅前)・7:02(芦沢口)・
  7:03(追分)の1本だけで、確定版では芦沢口・追分などのそば(徒歩3〜5分)が1〜2分間に合わず「通院不可」になっていた
- **確定版の「隠れ空白 9メッシュ・571人」のうち 8メッシュ・568人がこれにあたる**。隠れ空白の数値は
  「7時より前には家を出ない」という前提に強く左右される。応募資料で隠れ空白を挙げるときは、この前提を添える
- 空白メッシュ人口の変化は 568人(15,418人の3.7%)で、「空白地帯の高齢化率は2市全体より高い」という結論は変わらない

## 既知の限界

1. **徒歩は直線距離×1.3の近似**。川や線路で分断された場所は実際より甘く出る
2. **出発点はメッシュ中心**。500m四方の中の位置差(最大350m≒徒歩6分)は丸められる
3. **特定の1日(平日)のダイヤで計算**。冬ダイヤ・減便期は別途再計算が必要
4. デマンド交通・タクシー・鉄道は対象外。**到達時間はバス9フィードのみで計算している**
   (鉄道のフィードは読み込んでいない。駅とバス停の乗換・駅構内の徒歩も扱わない。
   2026-09-24 修正: 以前ここに「山形鉄道フィードは読み込むが」と書いていたが、
   フィード一覧に入れたことは一度もなく、下の限界6「バスのみで計算している」と
   矛盾していた。履歴を確認して事実に合わせた)
5. OSMのスーパー網羅性は地域差がある(第1部の調査で山形市内は実用的な水準と確認済み)
6. **JR在来線はオープンデータとして提供されておらず、本マップの到達時間はバスのみで計算している。**
   かみのやま温泉〜山形など鉄道が実質的な移動軸である区間では、実際より不利に評価される
7. **モビリティ・カルテ(`webapp/karte/`)の位置も上記2と同じメッシュ中心の近似**。
   住所やGPSで選ばれるのは「おうちのあたり(約500m四方)」のめやすで、1軒ごとの
   正確な数字ではない
8. カルテの住所検索は国土地理院の外部API(無料・キー不要)に依存する。
   停止・仕様変更のリスクがあり、その場合もGPS・地区選択の2経路で使い続けられる設計にした
9. カルテの総合評価(A〜E)は病院所要時間・通院可否からの機械的なめやすで、
   坂道・冬道・個人の歩行速度などは反映していない
10. **時刻表Web(第3部)の山形済生病院への行き・帰りだけ、病院の無料シャトルバスを含めている**
   (2026-10-07〜)。出典は山形済生病院「シャトルバス時刻表」(令和8年10月から。
   https://www.ameria.org/access/ )で、**オープンデータではない**ため手作業で GTFS にした
   (`gap_map/make_saisei_shuttle.py` → `feeds_manual/済生病院シャトル/`)。病院行きは途中下車
   できないので、ほかの行き先の経路には使わない。第2部の空白マップ(凍結数値)には含めない。
   停留所の位置の一部(山交ビル花屋前・山形駅交番前・長町酒店)は推定、おーばん山辺店は未収録。
   ダイヤ改正は自動では反映されない
11. **家を出る時刻は 7:00〜10:30 の30分おきで試している**(7時より前には家を出ない前提)。朝の便が少ない地区では
   この前提で通院可否が分かれる(山寺地区。上の「参考: 感度分析」)

## モビリティ・カルテのプライバシー

`webapp/karte/` は住所やGPSから「あなたの家の移動のようす」を表示する機能。
入力した住所は**この端末(ブラウザ)の中だけで使い、保存も自サーバーへの送信もしない**。
候補地点を調べるときだけ、国土地理院の住所検索API(https://www.gsi.go.jp/johofukyu/johofukyu41022.html)
に住所の文字列を送る。それ以外の通信先はGitHub Pages(静的ファイルの配信)のみで、
サーバー側で個人の入力を記録する仕組み自体を持たない。
