## 2. 見つかった不具合(重大 → 軽微)

### B-1【直した・重要】画面を開いたまま日付が変わると、前の日のダイヤで「つぎのバス」を出す

- 再現: 金曜の夜に かんたんモードの画面3を開いたままにする → 土曜0:00すぎ、30秒ごとの時計の更新で「つぎのバスは ごぜん8:01(あと481分)」(**平日の始発**)が出る。土曜の始発は「山交ビル」ごぜん7:32。下の注記も「きょうは「平日」ダイヤです」のまま
- 原因: `renderScreen3` で決めた「きょうのダイヤ」を、時計のタイマーが日付をまたいでも使い続けていた。スマホはタブを開いたまま翌朝に見ることがよくあるので、お年寄りが一番使う朝に間違えやすい
- 直し方: タイマーの中で日付が変わったら画面3を作り直す(3行)。直したあと同じ手順で、0:00:22 に「つぎのバスは ごぜん7:32」「土曜」に切り替わるのを確認

### B-2【直した】しっかりモードを印刷すると、表の中の「🗺 地図」が紙に出る

- 原因: 印刷用の `.no-print { display:none }` より、表の中の `.tt .map-link { display:inline-block }` のほうが CSS の強さ(詳細度)が上で、打ち消されていた
- 直し方: 印刷用の行に `.tt .map-link` を足す(1行)+ style.css の版番号を上げた。直したあと印刷メディアで地図リンク0個を確認

### B-3【提案のみ・中】乗り換えの「◯分 まち」が、歩いて乗り換える便では少なく(0分など)出る

- 再現: 例 みはらしの丘地区 → 行き先 f05 の平日11:20発「山形駅西口で おりて、山形駅前まで あるいて、…に のりかえ(**0分 まち**)」。全データで乗換59,663便のうち「0分 まち」が5,466便
- 原因: `make_itinerary` の `wait_min` は「乗り換え先に着いた時刻」からの待ちで、歩いて乗り換えるときは「最小の乗換余裕3分+歩く分」を引いたあとの値になる(同じ停での乗換は3分を含む)。そのため歩く乗り換えだけ「0分 まち」になり、`ride_min`(バスに乗る時間)に余裕と歩く分が混ざって長めに出る。「ＮＨＫ前」のように同じ名前で別ののりばへ歩く場合は「あるいて」の案内も出ない
- 直し方の案: 工場で `wait_min` を「1本目を降りてから2本目が出るまで」にそろえ、歩く分を `transfer.walk_min` として別に持たせ、画面は「(あるいて約◯分・◯分 まち)」と出す。工場・timetable.js・画面の3か所+再生成+照合。工数 半日〜1日。**再生成のついで(11月中旬)に入れるのがよい**

### B-4【提案のみ・中】バス停の名前に全角英数字が残っている(禁止語彙)

- 全2,356画面の検査で、「ＮＨＫ前」「セブンイレブン山形桧町１丁目店角」「本町・Ｑ１」が出た(全角英数字は plan_f4_ui §1 の禁止語彙。系統名とのりば番号はすでに半角化済みだが、バス停名は未対応)
- 直し方の案: 画面に出すときだけ `normalize("NFKC")` する(のりば番号の `platformText` と同じ考え方)。停名はデータの照合キー(乗り場の選び直し・停名索引)にも使っているので、**キーは変えず表示の直前だけ**変えること。かんたんの表示箇所が十数か所あるので小さい関数1つにまとめる。工数 1〜2時間

### B-5【提案のみ・中】かんたんモードに「早く出て同じバスに乗るだけ」の便が残る(しっかりでは消える)

- **気がかり1 の答え**: 第二地区 → ヤマザワ長岡店の平日 16:56 山交ビル発は「山交ビル → 山形駅前で降りる → 山交ビルまで歩いて戻る → 17:15 山交ビル発のバスで 17:58 着」という**ひと回りして戻ってくる便**で、同じ山交ビルから 17:15 の直通に乗っても同じ 17:58 に着く。しっかりの「すべて」で消えるのは**意図どおりで正しい**。おかしいのは、かんたんモード(と しっかりの「山交ビル」で絞り込んだ表)に出ること
- 原因: 工場の `drop_same_bus_earlier_rows` は「その便で乗れる**どの停**でも代わりの便がある」ときだけ消す。16:56 の便は保健所前からも乗れる(17:15 の便は保健所前を通らない)ため残る。かんたんは1つの乗り場だけを見せるので、その乗り場の中だけで比べれば消してよい
- 規模: かんたんで見せている便41,459本のうち約300本・133組(地区×行き先)。ひと回りして同じ停に戻る便は12本
- 直し方の案: 画面側の `kantanOutbound()` で乗り場を付け替えたあと、しっかりの `dropSameBusEarlierRows` と同じ比較をかける(同じ着・同じ最後のバス・同じ降りる停なら、家を一番遅く出られる行だけ残す)。10行ほど。ただし**照合の正解(地区ファイル)は変わらない**が、かんたんの見え方が変わるので、開発者の確認を経てから入れる。工数 1〜2時間

## 4. 既知の未決事項への意見

**(a) district_gap.json を公開するか** → **公開(コミット)を勧める**。中身は地区ごとの人口・高齢化率・空白人口などの集計だけで個人情報は無く、合計が第2版(11,455人・276,482人)と一致することを確かめた。しっかりモードの「この地区の交通状況」パネルは、時刻表から空白マップへ橋をかける作品の核(診断→処方箋)を一番短く見せる部品。コミット前に `python3 -m pytest gap_map/test_make_district_gap.py` を回し、ファイルを作った手順(make_district_gap.py)を runbook に1行足すとよい。

**(b) 所要時間が全部歩くより長い便(中川(きた)→みゆき会病院 平日06:10・85分)** → 何かの基準は入れたほうがよい。規模の見積もり(地区ファイルの全乗り場の行き71,302便、代表点から施設までの直線×1.3÷60で概算): 家を出てから着くまでが全部歩くより長い便 3,206便(4.5%)・325組、全部歩くより30分以上長い便 610便、「2倍以上かつ20分以上長い」便 308便。案は2つ:
- 案1(おすすめ): 「全部歩くより遅く着き、**しかも同じか遅く家を出て同じか早く着く別の便がある**」便だけ落とす(帰りで使っている frontier と同じ考え方)。06:10 便は 07:30 金瓶南発・07:35 着が同じ着なので落ちる。早朝にそれしか無い便は残るので「行けたはずの人が行けなくなる」心配が小さい
- 案2: 単純に「全部歩くより◯分以上長い便を落とす」。分かりやすいが、歩けない人には長くてもバスが要るので、しきい値の決め方が難しい
- どちらも工場と timetable.js の両方を変え、照合し直す(再生成と同じ回に)

**(c) 家族が代わりに「わが家」を登録する道(D2)** → 3-5 の第三者テストの結果を待つ方針に賛成。足すなら案C(しっかりモードで作った「わが家つきリンク」)より、**かんたんの画面1に「地図で家の場所を えらぶ」ではなく「住所で とうろく」(国土地理院API。カルテで実績あり)**のほうが、家族が本人のスマホを手にした1回で済む。ただし住所の文字列を外部APIへ送ることを画面に明記する(カルテと同じ)。

**(d) 応募資料の物語** → 「30.3%→45.5%」を軸にし、隠れ空白は数字の勾配ではなく**事例で語る**のがよい(2メッシュ・314人は「時刻表上は行けるのに、受診に間に合わない・帰れない人がいる」ことを示す実例として十分)。「近所の内科医院まで含めても」という第2版の保守的な定義は、それ自体が説得力になる(甘く数えてもなお11,455人)。

**(e) スマホ実機テスト(3-5)** → P-6 の5項目に絞って半日で。特に P-1(画面2の待ち時間)は実機の数字が無いと判断できない。

## 5. 確認できなかったこと・制約

- **メッシュ817地点の照合**: 1バッチ(205地点・4つおき)だけ回して全件一致。残り3バッチ(offset 1〜3、各12分ほど)は未実施
