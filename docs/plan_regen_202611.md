## 2. 各項目

### A. 乗り換えの「◯分 まち」と「バスに乗る時間」(✅ 2026-10-12 実施)

**何を**: 乗り換えの便に「乗り換えで歩く時間」を別に持たせ、「まち」を「1本目を降りてから2本目が出るまで − 歩く時間」にそろえる。画面は「(あるいて約◯分・◯分 まち)」と出す。

**なぜ**: いまの `wait_min` は、歩いて乗り換えるときだけ「乗換の余裕3分+歩く時間」を引いたあとの値になっている(同じ停での乗り換えは3分を含む)。そのため「山形駅西口で おりて、山形駅前まで あるいて…(**0分 まち**)」と出る(乗換59,663便のうち5,466便が0分)。実際には3分+歩く時間のゆとりがある。また `ride_min`(バスに乗る時間)に その3分と歩く時間が混ざって長く出る。「ＮＨＫ前」のように同じ名前の別ののりばへ歩く場合は、歩くことも書かれない。

**どこを**:
- 工場 `gap_map/export_web_data.py` の `make_itinerary`(`transfer = {...}` を作る所・`ride_min` の計算):
  - `transfer["walk_min"]` = 歩く乗り換えなら `round(walk_between の歩く分)`(余裕3分は含めない)、同じ停なら 0
  - `transfer["wait_min"]` = `second.depart − first.arrive − walk_min`
  - `ride_min` = `到着 − 出発 − wait_min − walk_min`
  - ※ `walk_between.arrive` は「到着+3分+歩く分」なので、歩く分は `walk_between.arrive − walk_between.depart − 3`(= `config.MIN_TRANSFER_MIN`)で取り出す
- 同じファイルの付け替え2か所(`_slim_to_board`・`drop_pointless_rows` の `ride_min` を計算し直す所)も「− wait − walk」に
- 端末計算 `webapp/engine/timetable.js` の `makeItinerary`・`slimToBoard`・`dropPointlessRows` を同じに
- 画面: `webapp/kantan/app.js` の `rowsFromBoard`(ride_min)と `rideStepsHtml` ののりかえ文、音声(`setupSpeakButton`)、
  `webapp/shikkari/app.js` の絞り込み2か所(ride_min)とのりつぎ欄。`walk_min` が無い古いデータでは今までどおり出す(後方互換)
- テスト `gap_map/test_export_web_data.py` の「`wait_min == 22`(歩いて着いてから乗るまで)」などを新しい決まりに書き換え、
  「歩く乗り換え」「同じ停の乗り換え」「同じ名前の別ののりば」の3つの小さなテストを足す

**検算**: pytest/代表点の照合(全2,356組)/817地点の照合4回/全データで「0分 まち」の数が大きく減ること・
`wait_min` が負になる便が0件であること/ブラウザで みはらしの丘地区 → f05 平日11:20 の表示

**決めてもらうこと**:
- 画面の言い方: 案1「(あるいて約3分・2分 まち)」/案2「あるいて約3分。のりかえまで 2分」。**おすすめ 案1**
- 余裕の3分を「まち」に含めるか(含めると同じ停の乗り換えと揃う)。**おすすめ 含める**(上の計算はそうなっている)

### B. 「ひと回り」の便を、その乗り場から見えなくする(✅ 2026-10-12 実施)

**何を**: 同じ乗り場から、**家を同じか遅く出て、同じバスで同じ時刻に着ける別の便**があるとき、その乗り場を元の便の
乗り場の候補(board_options)から外す。候補が全部外れたら便ごと落とす。主停が外れたら、残った候補のうち家にいちばん近い停へ付け替える
(`drop_pointless_rows` の付け替えと同じやり方)。

**なぜ**: 例 第二地区 → ヤマザワ長岡店 平日 16:56 山交ビル発は「山交ビル → 山形駅前で降りる → 山交ビルまで歩いて戻る → 17:15 山交ビル発」。
同じ山交ビルから 17:15 の直通に乗れば同じ 17:58 に着く。いまの `drop_same_bus_earlier_rows` は「その便が止まる**全部の**乗り場で代わりがある」ときだけ
落とすので、保健所前からも乗れるこの便は残り、かんたんモード(1つの乗り場だけ見せる)に出る。規模はかんたんで約300便・133組、
同じ停に戻ってくる便は12便。
**画面側でなく工場で直す理由**: かんたん(地区)・しっかりの絞り込み・わが家(端末計算)の3つが同じ答えになり、照合で守れる。
画面だけで直すと、しっかりの絞り込みとわが家に同じ直しを3回書くことになる。

**どこを**: 工場 `drop_same_bus_earlier_rows`(停ごとに比べて board_options を削る形に)と、端末計算 `dropSameBusEarlierRows`。
しっかりの画面側 `dropSameBusEarlierRows`(乗り場をまたぐ「すべて」用)はそのまま。

**検算**: pytest に「16:56 の型」の小さな例を足す/照合(代表点・817地点)/全データで「かんたんで見せる便のうち、同じ乗り場から家を遅く出て
同じバスで同じ時刻に着ける便がある便」が0件になること(レビューで使った数え方。報告書 B-5)/おすすめ乗り場(kantan_boards)の変化を数えて、
変わった組を目で確かめる

**決めてもらうこと**: 同点(家を出る時刻も同じ)のときに残す方。**おすすめ: 待ちの短い方**(今と同じ)

### C. 全部歩くより遅く、しかも別の便に負けている便を落とす(✅ 2026-10-12 実施)

**何を**: 次の2つが**両方**当てはまる行きの便を落とす。
1. 家を出てから着くまでが、家から行き先まで全部歩く時間(`walk_all`)より長い
2. 家を同じか遅く出て、同じか早く着く別の便がある(どちらかは厳しく良い)

**なぜ**: 中川(きた)→ みゆき会病院の平日 06:10 リナワールド前発(桜田で47分待ち・07:35着・85分)は、全部歩いても21分の所。
いまの `drop_pointless_rows` は「歩く時間が5分以上減るか」だけを見るので残る。地区ファイルの行きの便のうち、全部歩くより遅い便は
3,206便(4.5%)・325組。2. の条件をつけるのは、**それしか無い便(早朝の1本など)は残す**ため(歩けない人にはバスが要る)。
06:10 の便は、07:30 金瓶南発・07:35着が 2. に当たるので落ちる。

**どこを**: 工場 `build_entry` の `drop_pointless_rows` のすぐあと(`outbound_all` を作る前)に関数を1つ足す。端末計算 `buildEntry` も同じ。
帰りは `frontier_rows` で 2. の条件をすでに満たしているので、行きだけでよい。

**検算**: pytest/照合/落ちた便の数(見込み: 3,206便より少ない)と、便が0本になった組が増えていないこと(増えたら原因を見る)/
06:10 の便が消えて 07:30 が残ること/おすすめ乗り場の変化を数える

**決めてもらうこと**:
- 2. の「別の便」を、**同じ乗り場の中だけ**にするか、**全部の乗り場**にするか。全部にすると落ちる便は増えるが、かんたん(1つの乗り場)で
  代わりの無い便が消えることがある。**おすすめ: 全部の乗り場**(1. の「全部歩くより遅い」がついているので、消えても困る人は少ない)
- 1. に余裕をつけるか(例: 全部歩くより10分以上遅い)。**おすすめ: つけない**(まずは単純に)

### D. バス停の名前の全角英数字を半角にする(✅ 2026-10-12 実施)

**何を**: バス停の名前にも `normalize_text`(全角英数字→半角。NFKC)をかける。系統名・行き先表示にはすでにかけている。

配布ネットワークの停名1,256のうち47が変わり、変えたあとで同じ名前になってしまう組は0(2026-10-12 確認)。
カッコ「（往路）」も半角「(往路)」になる。

**どこを**:

**検算**: 照合(工場と配布ネットワークの両方を直さないと落ちる=直し忘れを見つけられる)/全データで停名の全角英数字が0件/
